# MPay 0.2.0 — установка и обновления

Для пользователей предназначен **подписанный release APK**, а не `app-debug.apk`. Версия рассчитана на Android 11 и новее. Это локальный каталог карт с распознаванием и ручным журналом расходов; реальная банковская оплата не подключена.

## Установка APK

Передайте пользователю `dist/MPay-0.2.0.apk`. Android может запросить разрешение на установку из браузера или файлового менеджера и выполнить проверку Play Protect. Это стандартные проверки установки вне магазина. Подпись приложения не гарантирует отсутствие репутационных предупреждений, и MPay не обходит системные проверки.

Подробности: [официальные пояснения о предупреждениях Play Protect](https://developers.google.com/android/play-protect/warning-dev-guidance). Для публичного распространения владелец также должен проверить применимые к стране и каналу требования [верификации разработчика Android](https://developer.android.com/developer-verification).

Включённая блокировка телефона необходима для открытия кошелька. MPay использует системный PIN/пароль/графический ключ либо сильную биометрию. PIN банковской карты не нужен.

Если раньше установлен debug APK из этого проекта, Android не примет release APK как обновление из-за другой подписи. Не удаляйте установленную версию без учёта потери её локальных данных. Для новой установки используйте устройство без debug-версии; для разработки в Android Studio используйте debug-сборку.

## Подпись и будущие обновления

Постоянный ключ находится в `.signing/mpay-release.p12`, локальная конфигурация сборки — в `.signing/signing.properties`. Оба файла исключены из Git. **Сохраните защищённую резервную копию обоих файлов у владельца проекта.** Не передавайте их вместе с APK и не публикуйте: с этим ключом подписываются будущие обновления. При потере ключа обычное обновление уже установленного приложения станет недоступно.

SHA-256 сертификата выпуска:

```text
8492d94d80bfb49ba616126e3e3f6389db007f874e91d47641104be01775af24
```

Сборка с настроенным JDK 17:

```powershell
.\gradlew.bat :app:assembleRelease :app:testDebugUnitTest :app:lintRelease
```

Release APK: `app/build/outputs/apk/release/app-release.apk`. Повышайте `versionCode` при каждом обновлении. В репозитории без локального ключа не следует распространять unsigned APK.

## Android Studio

Проект согласован с установленной Android Studio Hedgehog: Android Gradle Plugin 8.2.2, SDK/target 34, Java 17. Открывайте корневую папку `MPAY`, а не отдельный каталог `app`. Запустите **File → Sync Project with Gradle Files**, затем выберите конфигурацию `MPay` или Android App с модулем `MPAY.app.main` и устройство, нажмите Run.

На этом компьютере для Gradle user home выбран `C:\Users\Admin\Desktop\MPAY\.gradle-local`, поскольку общий кэш `C:\Users\Admin\.gradle` выдавал ошибку перемещения временных workspace. Путь задаётся в Settings → Build, Execution, Deployment → Build Tools → Gradle. На другом компьютере этот абсолютный путь нужно заменить собственным путём к локальному кэшу.

Это конфигурация для установленной IDE и распространения APK напрямую. Публикация в магазине является отдельным этапом: нужно сверить актуальные требования магазина к target SDK, обновить инструментальную цепочку при необходимости, заполнить данные издателя и опубликовать политику конфиденциальности. Шаблон локальной политики находится в `PRIVACY.md`.

## Проверки

Сборка release, debug, пакета Android-теста и четыре unit-теста выполнены успешно 2 ноября 2026 года. Release Android Lint завершился без ошибок (5 предупреждений о версии SDK/библиотеки и ресурсах). Подпись проверена `apksigner`; release не имеет отладочного режима и разрешения INTERNET. APK установлен на эмулятор Android 11, тест `LaunchTest` прошёл: стартовый экран остаётся заблокированным до аутентификации, кнопки входа и настройки защиты доступны. Отчёт — `dist/launch-test.txt`. Проверка проведена через штатный Android InstrumentationTestRunner; Gradle UTP в offline-режиме не использовался из-за отсутствующей зависимости. После исправления кэша запуск через Run в Android Studio также завершился успешно: IDE собрала приложение, установила APK и открыла `MainActivity` на `Medium Phone API 30`. Эти проверки не заменяют проверку на разных устройствах и не являются сертификацией платёжного приложения.
